# docatlas 요구사항

문서 기준: 2026-10-28. 문서 기반 개발(Doc-Driven Development)을 사용하는
프로젝트를 위한 독립 CLI 도구다. DDD는 이 문서에서 이 의미로 사용한다.

[설계](./DESIGN.md) · [구현 계획](./IMPLEMENT.md) · [수동 검증](./MANUAL_TEST_CHECKLIST.md)

## 목적과 사용 맥락

개발자가 프로젝트 곳곳에 쌓인 문서를 찾고, 기능의 상하위 구조와 관련 문서를
한눈에 파악하도록 돕는다. 개발 중 CLI 명령을 실행해 로컬 브라우저에서 사용한다.

특정 저장소에 포함된 기능이 아니라 여러 프로젝트에 설치하는 별도 패키지다.
문서를 업무 진행률로 해석하는 기능보다 문서 탐색과 읽기에 우선순위를 둔다.

2026-10-28 사용자 결정(RQ-19): 이 저장소는 문서 지도 도구이면서 이 프로젝트가 말하는 DDD,
곧 Doc-Driven Development 워크플로우 규칙의 본거지다. 방법론 설명·에이전트 스킬과 룰·문서 지도를
한 저장소에서 소개한다. 문서 탐색과 읽기를 우선하는 제품 범위는 그대로다.

사용자 설명(2026-10-28): 작은 부분까지 문서로 만들면 과하고, 문서가 쌓이면 사람이 어느 정도 개입해 관리해야 한다.
사람이 직접 다 정리할 필요는 없지만, 문서의 분포와 내용을 알고 있어야 에이전트에게 정리를 시킬 수 있다.
사람이 보는 문서 뷰어를 만든 이유도 그것이다. README와 METHOD는 이 이유로 docatlas를 소개한다(DC-22).

## 요구사항의 상태

- **확인됨**: 사용자가 직접 요청했거나 선택한 내용.
- **설계 제안**: 기본 동작을 구체화한 초안. 사용자 확인 사항과 혼동하지 않는다.
- **구현됨**: 실제 코드와 검증 근거가 있는 상태. 요구사항 확인과 별개다.
- 세부 결정은 설계의 DC/IC 체크리스트에서 관리한다. TBD를 임의로 확정된 것으로 표시하지 않는다.

## 첫 사용 가능 단계와 확장

1. 문서 수집과 기능 계층을 만든다.
2. CLI로 서버·브라우저를 열고 카드와 문서 선택을 연결한다.
3. Markdown 읽기와 기본 링크를 완성한다. 이 지점이 첫 사용 가능 단계다.
4. 검색·자동 갱신·이동 문서 연결을 추가한다.
5. Test Hardening과 Integration Test를 거쳐 배포를 준비한다.

부분 문서 묶음의 탐색은 수집 단계부터 다룬다. 실제 프로젝트를 사용할 때
문서 4종을 모두 새로 만들거나 기존 파일을 옮기는 작업을 전제로 하지 않는다.

## 설치·실행 제약

- 2026-10-28 사용자 선택: npm package.json의 name은 docatlas, GitHub 저장소는 superlucky84/docatlas로 변경한다.
  기본 실행 명령은 docatlas이고 기존 docmap·ddd-docmap은 호환 이름으로 제공한다.
- 2026-10-28 사용자 요청: 프로젝트별 개발 의존성 설치와 루트에서의 짧은 명령 실행을 지원한다.
  사용자가 프로젝트별 설치 후 npx / pnpm으로 실행하는 방식을 선택했고 새 명령은 docatlas다.
  npm 예제는 설치된 버전만 실행하도록 npx --no-install docatlas를 사용한다.
  전역 런처나 셸 PATH 자동 변경은 이번 구현 범위에 포함하지 않는다.
- 설치는 사용자가 선택하는 manifest/lockfile/node_modules 변경이다. 실행 중 원본 보존과 설치 단계를 구분한다.
- 사용자가 MIT를 선택했다. 첫 공개 패키지 후보는 docatlas@0.1.0이며 LICENSE를 포함한다.
  사용자가 0.1.0과 0.2.0의 npm 배포를 완료했다. 2026-10-28 사용자 요청으로 Python·Java 기본 제외와
  에이전트 스킬 설치를 포함한 다음 후보를 0.3.0으로 확정했다. 0.2.1은 게시하지 않은 준비 버전이다.

  둘 다 있으면 새 파일만 사용한다. 새 파일이 잘못됐을 때 이전 파일로 오류를 우회하지 않는다. JSON version 1은 유지한다.
- --docs-dir는 프로젝트 루트 기준 상대 디렉터리를 반복 지정해 현재 포함 범위에 추가한다.
  --all-md는 include 대신 모든 .md를 포함 후보로 삼는다. 제외·ignore·심볼릭 링크 정책은 항상 유지한다.
  기본 발견은 기존 docs/·표준 4종을 유지한다. include/exclude의 기본값 대체와 CLI 우선순위는 설계를 따른다.
- npm 배포 파일은 agent-kit/·bin/·src/와 자동 포함되는 README·package.json·LICENSE로 한정한다. agent-kit/는 RQ-17로 추가했다.
  기준 문서와 과거 패치는 GitHub에서 제공하며 npm tarball에는 개발 기록을 포함하지 않는다.
- README는 미설치 npx 실행·npm/pnpm 로컬 설치·배포 전 tarball 설치를 구분하고 현재 cwd가 기본 루트임을 설명한다.
- 사용자는 이번 작업을 배포 준비까지만 진행하기로 선택했다. 실제 npm publish는 이번 범위에서 실행하지 않는다.
- 선언한 최소 Node.js는 22다. 최근 설치 통합 검증은 macOS 15.6.1 / Node.js 22.12.0·24.22.1이다.
- 선언한 하한 22.0과 다른 OS는 미검증이다. 설치 검증 성공과 최종 지원 선언을 구분한다.
- 최종 지원 OS와 최소 버전 검증은 배포 전 결정한다.
- 대상 프로젝트의 소스 빌드나 설정 파일 실행 없이 Markdown을 읽는다.
- 웹 화면은 배포 패키지에 미리 빌드해 포함하는 방식을 제안한다.
- 본문과 인덱스는 로컬에서 처리하며 기능 사용에 외부 계정 로그인을 요구하지 않는다.

## 데이터와 기존 문서

- 원본 Markdown과 문서 간 링크가 기준이다. 도구가 원본을 편집하거나 이동하지 않는다.
- 설정은 선택 사항이며 기존 문서에 별도의 메타데이터 작성을 요구하지 않는다.
- 기본 발견 범위 밖의 문서는 설정으로 추가할 수 있게 한다.
- 인덱스는 재생성 가능한 파생 데이터다. 장기 보관할 별도 문서 데이터베이스를 요구하지 않는다.
- 설정 형식을 변경할 때 버전을 구분하고, 읽을 수 없는 버전은 명확히 안내한다.
