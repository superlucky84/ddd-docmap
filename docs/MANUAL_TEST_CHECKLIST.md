# docatlas 수동 검증 체크리스트

문서 기준: 2026-10-28.
[요구사항](./REQUIREMENTS.md) · [설계](./DESIGN.md) · [구현 계획](./IMPLEMENT.md)

수집기·서버·지도·서식 읽기·참조 탐색을 구현했다. 아래 수동 인수 전체의 상태와
자동 검증한 부분을 구분한다. Phase 4에서 검색·갱신·명시적인 문서 이동 연결의 자동 검증을 추가했다.
부트스트랩의 help/version·패키징 검사는 구현 계획의 과거 기록이다.

## 가상 프로젝트

F-01~03은 test/helpers/projects.js와 테스트가 임시 디렉터리에 생성한다.
예제 Markdown 사본을 저장소에 쌓지 않으며 테스트 종료 시 임시 디렉터리를 정리한다.
F-04는 test/helpers/reading.js, F-05·06은 이동 연결·다중 실행 테스트,
F-07은 test/integration/package.test.js, F-08은 test/helpers/scale.js가 생성한다.
F-09(에이전트 스킬 설치)는 test/helpers/agent-kit.js와 test/integration/agent-kit.test.js가 임시 HOME·프로젝트로 만든다.

### F-01 — 기본 계층과 부분 문서

```text
sample-project/
  README.md
  docs/
    catalog/
      REQUIREMENTS.md
      DESIGN.md
      IMPLEMENT.md
      MANUAL_TEST_CHECKLIST.md
      filters/
        DESIGN.md
    shared/
      README.md
    notes/
      RESEARCH.md
  src/
    helper/
      REQUIREMENTS.md
  node_modules/demo/docs/REQUIREMENTS.md
  dist/docs/DESIGN.md
```

기본 발견 문서는 **8개**다. 루트 README와 의존 패키지·산출물의 문서는 제외한다.
catalog는 자체 4종과 filters 자식을 함께 가진다. shared는 README만 있어도 표시한다.
src/helper의 표준 문서는 docs 밖에서도 발견한다.

## 실행 기록

각 실행에 다음을 남긴다.

- 날짜, OS와 버전, Node 버전.
- 검증하는 패키지 버전·커밋과 설치 방법.
- 예제, 실행 명령, 관찰한 결과.
- pass / fail / 미실행. 실패는 재현 절차와 관련 결함을 연결한다.
- 원본이 바뀌지 않았는지 확인한 방법.

필수 항목의 미실행은 통과가 아니다. 예제·측정 환경이 다른 과거 결과를 새 결과로 쓰지 않는다.
