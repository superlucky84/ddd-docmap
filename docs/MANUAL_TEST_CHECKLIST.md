# ddd-docmap 수동 검증 체크리스트

문서 기준: 2026-10-27.
[요구사항](./REQUIREMENTS.md) · [설계](./DESIGN.md) · [구현 계획](./IMPLEMENT.md)

수집기·서버·카드 지도를 구현했다. 아래 수동 인수 전체의 상태와
자동 검증한 부분을 구분한다. 서식 렌더링·링크·검색·갱신은 아직 미구현이다.
부트스트랩의 help/version·패키징 검사는 구현 계획의 과거 기록이다.

## 가상 프로젝트

F-01~03은 test/helpers/projects.js와 테스트가 임시 디렉터리에 생성한다.
예제 Markdown 사본을 저장소에 쌓지 않으며 테스트 종료 시 임시 디렉터리를 정리한다.
F-04~08의 전체 흐름은 해당 구현 단계에서 확장한다.

### F-01 — 기본 계층과 부분 문서

```text
sample-project/
  README.md
  docs/
    catalog/
      REQUIREMENTS.md
      DESIGN.md
      IMPLEMENT.md
      MANUAL_TEST_CHECKLIST.md
      filters/
        DESIGN.md
    shared/
      README.md
    notes/
      RESEARCH.md
  src/
    helper/
      REQUIREMENTS.md
  node_modules/demo/docs/REQUIREMENTS.md
```

기본 발견 문서는 **8개**다. 루트 README와 의존 패키지·산출물의 문서는 제외한다.
catalog는 자체 4종과 filters 자식을 함께 가진다. shared는 README만 있어도 표시한다.
src/helper의 표준 문서는 docs 밖에서도 발견한다.

## 실행 기록

각 실행에 다음을 남긴다.

- 날짜, OS와 버전, Node 버전.
- 검증하는 패키지 버전·커밋과 설치 방법.
- 예제, 실행 명령, 관찰한 결과.
- pass / fail / 미실행. 실패는 재현 절차와 관련 결함을 연결한다.
- 원본이 바뀌지 않았는지 확인한 방법.

필수 항목의 미실행은 통과가 아니다. 예제·측정 환경이 다른 과거 결과를 새 결과로 쓰지 않는다.

## 릴리스 판정

Phase 3은 기본 탐색·읽기의 첫 검토 시점이다. 전체 제품 릴리스에서는
채택한 요구사항에 대응하는 모든 필수 항목을 pass로 만든다.

제안 기능을 후속으로 옮기면 요구사항·설계·계획·이 문서의 범위를 함께 바꾼다.
배포 전 미실행·실패 항목과 지원하지 않는 환경을 명시한다.
공개 저장소나 도움말 실행만으로 제품 인수를 통과했다고 기록하지 않는다.
