# 설계

[요구사항](./REQUIREMENTS.md)에 대응하는 초기 설계다.
여기에 기록한 문서 수집기·서버·화면은 구현 전이며
[구현 계획](./IMPLEMENT.md)에서 단계를 관리한다.

## 전체 구조

단일 배포 패키지 내부에서 책임을 분리한다.

```text
CLI → 프로젝트 루트 결정 → 문서 수집기 → 문서 인덱스
                                      ↓
                                로컬 서버 → 웹 화면
                                      ↑
                               원본 파일 변경 감지
```

- CLI: 인자, 서버 실행·재사용·종료, 브라우저 열기.
- 수집기: 문서 발견, 기능 묶기, 계층과 상대 링크의 기준 계산.
- 인덱스: 제목·설명·본문 검색에 사용할 읽기 모델.
- 서버: 로컬 문서와 패키지에 포함된 화면 제공.
- 화면: 지도, 문서 선택, Markdown 읽기와 탐색 상태.

## 화면 제안

왼쪽 지도와 오른쪽 읽기 영역을 둔다. 지도는 가로로 얇은 기능 카드로 구성한다.

- 화살표: 하위 기능 펼치기·접기.
- 카드 본문: 해당 기능의 문서 선택 항목 펼치기.
- 문서 선택 항목: 오른쪽 본문 열기.
- 상위 기능도 자체 문서를 가질 수 있다.
- 4종은 있는 항목을 표시하며 README·공통 계약·조사 문서도 접근할 수 있게 한다.
- 본문에 집중할 때 지도를 접는 동작은 사용성 검토에서 확정한다.
- 작은 화면의 전환 방식과 구체적인 카드 크기는 TBD다.

## 문서 발견과 계층

현재 작업 디렉터리를 실행 대상의 기본값으로 제안한다.

기본 발견 후보는 docs 하위 Markdown과 이름이 일치하는 표준 4종 문서다.
README만 있는 공통 문서도 docs 아래에 있으면 수집 후보가 된다.
node_modules, .git, 빌드 산출물 등은 제외한다.

같은 디렉터리의 문서를 기능으로 묶는다. 상위 디렉터리가 문서 묶음이 아니더라도
구조를 안내하는 그룹으로 표현할 수 있어야 한다. 기술 폴더를 화면에서 생략하는
규칙과 사용자 지정 그룹은 DC-04에서 확정한다.

문서 이동을 안내하는 짧은 문서는 현재 기준 문서와 연결한다.
문장만으로 이동을 확신하기 어려운 경우 자동으로 합치지 않고 설정 보정 후보로 남긴다.

## 초기 데이터 모델

| 모델 | 주요 필드 | 역할 |
| --- | --- | --- |
| Project | id, root, displayName | 실제 경로가 같은 실행 대상을 식별한다. |
| FeatureGroup | id, parentId, title, summary, documentIds | 계층과 기능별 문서 묶음을 표현한다. |
| SourceDocument | id, relativePath, groupId, kind, title, summary, canonicalId | 원본 문서를 식별하고 선택·링크를 연결한다. |

- id의 정확한 생성 방식은 TBD다. 상대 경로 기반 식별을 우선 검토한다.
- kind는 requirements, design, implementation, manual-test, readme, research, other를 제안한다.
- 제목과 설명은 기존 본문에서 추출하며 보정 설정이 있으면 우선한다.
- 원본 본문과 검색용 가공 결과를 구분한다.
- 표준 파일 수를 구현 완료율이나 문서 품질 점수로 해석하지 않는다.

## 읽기와 링크

Markdown 표, 코드 블록, 제목 앵커를 지원한다.
상대 링크는 현재 문서의 실제 디렉터리를 기준으로 해석한다.

다른 Markdown은 뷰어에서 열고 뒤로 가기로 돌아올 수 있게 한다.
이미지·첨부 파일·코드 링크를 어떻게 여는지는 DC-07에서 정한다.
기존 Markdown에 포함된 HTML은 렌더링 정책을 정하고 그 정책에 따라 처리한다.

문서 제공 API는 프로젝트 루트 안의 허용된 문서·자산만 읽는다.
경로 정규화와 심볼릭 링크 처리 후에도 이 경계를 지킨다.

## 로컬 실행과 배포

- 웹 서버는 로컬 loopback에 바인딩한다.
- 패키지 설치 경로와 읽을 프로젝트 경로를 구분한다.
- 서버를 재사용한다면 프로젝트의 실제 경로를 대조한다.
- 백그라운드 실행을 채택할 경우 종료 명령, 오래된 실행 정보, 포트 충돌을 함께 다룬다.
- npm tarball에 CLI, 런타임 모듈, 미리 빌드한 화면을 포함한다.
- 현재 뼈대에는 서버나 화면이 없으며 CLI 도움말과 버전만 동작한다.
