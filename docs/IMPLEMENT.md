## 검증 예제와 기록

F-01~08의 구체적인 구성은 [수동 검증의 가상 프로젝트](./MANUAL_TEST_CHECKLIST.md#가상-프로젝트)를 따른다.
가상 예제는 저장소에 포함할 수 있는 내용으로 만들며 기업의 실제 문서를 복사하지 않는다.

### 기존 부트스트랩 — 2026-10-27

macOS / Node.js 24.21.0 / npm 11.19.0에서 실행했다.

- npm run check: CLI 진입점과 모듈 문법 검사 통과.
- npm pack: 실행 파일·모듈·4종 문서·README·AGENTS 포함 확인.
- tarball을 별도 임시 프로젝트에 오프라인 설치: 통과.
- 설치 CLI --help / --version: 종료 0, 출력 확인.
- 잘못된 인자: 종료 2, 안내 확인.
- 원본과 설치 패키지의 상대 Markdown 링크 13개: 통과.
- 공개 저장소와 초기 main push: 완료.

이는 당시 뼈대의 기록이다. Node.js 22·다른 OS·문서 수집기·브라우저 화면의
검증으로 확대 해석하지 않는다.

### 이번 문서 갱신

2026-10-27, 동일한 macOS / Node.js 24.21.0 환경에서 적용할 문서 사본을 검사했다.

- 기준 4종·README·AGENTS의 상대 링크와 앵커 19개: 통과.
- RQ/PR/DC/IC/M/F 식별자 참조, 인수 항목 15개와 가상 예제 8개: 통과.
- Phase 0~7의 기준 테스트·검증과 종료 기준: 확인.
- 사용자 선택인 포그라운드 기본 실행과 Ctrl+C 종료의 문서 간 일치: 확인.
- npm pack --dry-run: 기준 4종·README·AGENTS와 기존 CLI 파일의 포함 확인.
- 제품 인수 M-01~15: 미실행. 제품 코드와 기능 구현 상태는 이번 기록으로 바꾸지 않는다.

### 재개 순서

1. 작업 트리를 확인한다. git reset/clean이나 기존 Phase 3·4 변경 되돌리기를 하지 않는다.
2. 패치 대상 파일을 phase5-baseline.json과 비교한다. 달라졌으면 수동 병합하고 덮어쓰지 않는다.
3. 저장소 루트에서 아래 명령으로 패치를 검토·적용한다. 패치 적용 자체는 커밋을 만들지 않는다.

~~~sh
git apply --check docs/handoff/phase5-wip.patch
git apply docs/handoff/phase5-wip.patch
npm ci --offline --ignore-scripts --no-audit --no-fund --cache /private/tmp/ddd-docmap-phase1-npm-cache
npm run check
npm test
DOCMAP_BROWSER_CHANNEL=chrome npm run test:browser
~~~

오프라인 캐시가 없으면 정상 npm 설치로 대체한다. loopback/Chrome 실행이 차단되면 실행 권한을 요청한다.
이미 패치를 적용했다면 중복 적용하지 않고 현재 변경을 확인한다.

4. 다른 테스트와 동시에 실행하지 않고 npm run benchmark -- --browser를 실행한다.
   비교용 사본에서는 createProjectStore의 scanProject 호출에서 previous 인자만 제거하고 같은 명령을 쓴다.
   환경·표본·유휴 CPU·RSS와 최종 수치를 기록한 뒤 로컬 회귀 기준을 정한다.
5. 필요 시 개선 후 관련 회귀·npm pack --dry-run·설치/문서 검증을 마치고 기준 4종의 상태를 갱신한다.
6. Phase 5 종료 기준을 충족하면 Phase 6으로 간다. 커밋할 때는 사용자 선호대로 영문 메시지를 사용한다.
