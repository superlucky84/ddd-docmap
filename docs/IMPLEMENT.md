# 구현 계획

[요구사항](./REQUIREMENTS.md), [설계](./DESIGN.md),
[수동 검증](./MANUAL_TEST_CHECKLIST.md)을 함께 갱신한다.

## 현재 구현 상태

도움말·버전을 출력하는 CLI 뼈대만 있다.
문서 수집기, 지도 화면, Markdown 뷰어, 로컬 서버, 검색·변경 감지는 미구현이다.

## Phase 0 — 공개 프로젝트 부트스트랩

- [x] 독립 패키지 manifest와 실행 진입점.
- [x] README와 AGENTS.md.
- [x] 4종 기준 문서와 미결정 사항.
- [ ] 문법 검사, CLI 실행, tarball 내용 검증.
- [ ] GitHub 공개 저장소 생성과 첫 커밋 push.

기준 검증: npm run check, CLI의 help/version/잘못된 인자 실행, npm pack --dry-run.
종료 기준: 선언된 CLI가 실제로 동작하고 공개 main 브랜치에서 초기 문서와 코드를 확인한다.

## Phase 1 — 문서 수집기와 계층

- [ ] DC-04·05의 기본 발견·제외·제목·설명 규칙 확정.
- [ ] docs 하위 Markdown과 docs 밖의 표준 문서 발견.
- [ ] 같은 디렉터리의 문서 묶기와 상하위 그룹 구성.
- [ ] 상위 자체 문서, 일부 문서만 있는 기능, 공통 README, 이동 안내 예제.
- [ ] 선택 설정의 최소 계약과 오류 안내.

기준 테스트: 완전/부분 4종, 중첩 기능, docs 밖 표준 문서, 제외 경로,
한글·공백 경로, 중복 제목을 가진 가상 프로젝트.
종료 기준: 파일 수와 그룹 관계를 재현 가능한 인덱스로 만들고 M-01·02·09의
수집 관련 조건을 자동 검증한다.

## Phase 2 — 로컬 서버와 문서 지도

- [ ] DC-06과 DC-08의 최초 동작 방식 확정.
- [ ] 실행 프로젝트와 설치 패키지 경로 분리.
- [ ] loopback 서버와 브라우저 실행.
- [ ] 얇은 카드, 하위 그룹 펼치기, 문서 선택.
- [ ] 기능 선택과 본문 영역의 탐색 상태.
- [ ] 문서 0개와 읽기 실패 상태.

기준 테스트: 다른 cwd에서 실행, 프로젝트 루트 경계, 포트 충돌,
상위 문서와 하위 그룹이 공존하는 탐색.
종료 기준: CLI로 브라우저를 열어 실제 디스크의 기능과 문서를 선택할 수 있다.
M-03과 M-08의 기본 실행 조건을 확인한다.

## Phase 3 — 읽기·검색·변경 반영

- [ ] DC-07·09 확정.
- [ ] Markdown 표·코드·목차와 상대 링크·앵커.
- [ ] 제목·경로·본문 검색과 결과 문맥.
- [ ] 문서 수정·추가·삭제의 반영.
- [ ] 이전 문서 주소와 현재 기준 문서의 연결.
- [ ] 선택 문서 삭제와 링크 대상 미발견 안내.

기준 테스트: 상대 경로와 앵커, 이미지·외부 URL, 원본 HTML 정책,
한글 검색, 변경 중 열린 문서, 이동 안내의 오탐 방지.
종료 기준: M-04~07·10에 대응하는 읽기와 탐색 흐름이 동작한다.

## Phase 4 — Test Hardening

- [ ] 빈 폴더, 중복 이름, 잘못된 설정, 읽을 수 없는 파일.
- [ ] 심볼릭 링크와 프로젝트 밖 경로 접근 경계.
- [ ] 파일 감지 종료·연속 갱신·삭제 후 복구.
- [ ] 서버 재사용, 종료, 오래된 실행 정보와 다중 프로젝트.
- [ ] 키보드 탐색, 포커스 표시, 작은 화면과 긴 표.
- [ ] 대표 규모의 가상 문서에서 수집·검색 시간을 기록하고 예산 확정.

기준 테스트: 앞 단계의 전체 회귀와 실패 경로 테스트. 시간 기준은 실행 환경을
기록한 측정 후 정하며 현재는 TBD다.
종료 기준: 재현 가능한 주요 실패 경로를 검증하고 열린 결함의 처리 방침을 기록한다.

## Phase 5 — Integration Test

- [ ] npm pack으로 만든 tarball을 다른 임시 프로젝트에 설치.
- [ ] Node 앱과 다른 언어를 사용하는 가상 프로젝트에서 동일한 실행 검증.
- [ ] 두 프로젝트를 동시에 열고 각자의 문서와 상태를 유지.
- [ ] 문서 작성 → 화면 반영 → 링크 이동 → 종료의 전체 흐름.
- [ ] 패키지의 빌드된 화면 포함과 설치 위치 독립성.
- [ ] 구현에 없는 최소 런타임·OS 지원을 문서에 표시하지 않는지 확인.

기준 테스트: 실제 tarball 설치를 사용한 CLI/브라우저 통합 검증과 M-01~12.
종료 기준: 소스 저장소 밖에서 설치한 도구로 핵심 흐름이 재현되며
대상 프로젝트의 문서 변경 없이 동작한다.

## Phase 6 — 배포 준비

- [ ] DC-10의 라이선스·패키지 이름·배포 경로·지원 OS 결정.
- [ ] 사용법, CLI 옵션, 설정 예제와 릴리스 버전 정리.
- [ ] 합의된 지원 환경의 CI 검사.
- [ ] 배포 파일과 문서의 실제 기능 일치 확인.
- [ ] 배포 대상과 버전을 명시한 릴리스 작업.

기준 테스트: 설치·실행 통합 검증과 배포 tarball 검사.
종료 기준: 라이선스와 배포 대상이 확정되고 릴리스에 필요한 검증 결과가 남는다.
GitHub 저장소 초기화는 이 배포 작업과 구분한다.

## 검증 이력

부트스트랩 검증 실행 후 아래에 실제 결과를 기록한다.
향후 화면·통합 검증은 현재 완료된 것으로 표시하지 않는다.
